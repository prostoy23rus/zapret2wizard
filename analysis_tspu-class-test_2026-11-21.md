# Анализ репозитория tspu-class-test — что полезно для zapret2wizard

**Дата:** 2026-11-21
**Источник:** https://github.com/saitkul/tspu-class-test (v2.5, 38 звёзд, GPL-2.0)
**Кем анализируется:** zapret2wizard team (prostoy23rus/zapret2wizard)

## TL;DR

tspu-class-test — LuCI-приложение, которое за 5–15 минут определяет «класс ТСПУ»
вашего провайдера (34 тестовые стратегии × TLS 1.2/1.3), печатает вердикт
(L0-/L0/L2/особый/аномалия) и генерирует 8 готовых профилей под ваш ТСПУ.
Для zapret2wizard здесь есть 5 конкретных вещей, которые можно забрать сразу,
и 2 архитектурные идеи на будущее.

---

## 1. Новые механики десинхронизации для пресетов (МОЖНО ЗАБРАТЬ СЕЙЧАС)

Наш zapret-antidpi.lua УЖЕ реализует функции tls_client_hello_clone
(строка 367) и send (строка 90), но zapret2_presets.json их НЕ использует.
tspu-test подтверждает их эффективность строками 32–34:

| № | Стратегия | Механика |
|---|---|---|
| 32 | --payload=tls_client_hello --lua-desync=tls_client_hello_clone:blob=hs32 --lua-desync=fake:blob=hs32:tcp_md5:repeats=6 | клон-фейк: фейк с КЛОНИРОВАННЫМ ClientHello клиента |
| 33 | то же + --lua-desync=multidisorder:pos=midsld | клон-фейк + нарезка |
| 34 | --payload=tls_client_hello --lua-desync=send:repeats=2 --lua-desync=multidisorder:pos=midsld | send-эхо: копии hello серверу, шум DPI |

Также в пресетах отсутствуют:

- **badsum-пара (механика «дробилки»):** multisplit:blob=fake_default_tls:badsum:pos=2:nodrop:repeats=4 + 7-точечный шред. Ключевое отличие nodrop: шумовой пакет не подменяет сегмент, а добавляется.
- **payload=all (двухсторонний шред):** режется не только ClientHello, но и ServerHello — ломает классификацию ТСПУ по ответу сервера. В наших пресетах payload=all отсутствует полностью.
- **7-точечный шред:** pos=1,sniext+1,host+1,midsld-2,midsld,midsld+2,endhost-1 — у нас есть (3 вхождения), но не в связке с badsum-парой.
- **seqovl=1** (простой разрез без паттерна) и **двухпакетный hello** multisplit:pos=1 (имитация kyber-браузеров) — отсутствуют как отдельные пресеты.

**Действие:** добавить 8–10 стратегий в turbo_strategies/пресеты: клон-фейк (32/33), send-эхо (34), badsum-пара + 7-шред (20/21), payload=all варианты (23, 28/29), двухпакетный hello (17). Всё это уже поддерживается нашим nfqws2-набором.

## 2. Готовая классификация «КЛАСС ТСПУ» (МОЖНО ПОРТИРОВАТЬ)

Логика вердикта — ~150 строк AWK (строки 221–371 tspu-test), полностью портируема. Классы:

- **L0-** — нарезка пробивает без фейков; чистый multisplit склеивается → multidisorder:pos=midsld + seqovl
- **L0** — обратный порядок пробивает → достаточно multidisorder
- **L2** — нарезка только с фейком → фейк + нарезка
- **особый** — голый фейк проходит, нарезка режется → чистый фулинг
- **аномалия** — прямой разрез пробивает, обратный собирается → multisplit/seqovl
- **не определён** — флапнуло → автоповтор с ожиданием 8 с и 5 повторами

Отдельно по TLS 1.2 и TLS 1.3 (могут различаться!). Наш сканер находит рабочие стратегии, но НЕ классифицирует класс ТСПУ и не даёт минимально достаточную рекомендацию. Приоритетный список рекомендаций: 1 4 6 5 22 17 2 18 19 20 21 24 25 26 27 28 29 30 31 11 12 13 14 15 16 33 32 34 23 7 8 9 10 3.

**Действие (0.37.x):** после скана прогонять компактный классификационный корпус (20–30 строк) и показывать «Класс ТСПУ вашего провайдера» + одну минимальную рекомендацию.

## 3. Готовый шаблон «Универсальная лестница» — проверен на НАШЕМ firmware

Функция communityTemplate() в view (строки 1218–1232) — профиль, подтверждённый на флапающих ТСПУ RouteRich 25.12.6 (наш же роутер!):

```
--out-range=-s34228
--payload=all
--in-range=-s5556
--lua-desync=circular:fails=2:time=60:retrans=2:nld=2:reset
--in-range=x
--lua-desync=multisplit:blob=fake_default_tls:badsum:pos=2:nodrop:repeats=4:strategy=1
--lua-desync=multisplit:pos=1,sniext+1,host+1,midsld-2,midsld,midsld+2,endhost-1:strategy=1
--lua-desync=multidisorder:blob=fake_default_tls:badsum:pos=2:nodrop:repeats=4:strategy=2
--lua-desync=multidisorder:pos=1,sniext+1,host+1,midsld-2,midsld,midsld+2,endhost-1:strategy=2
--lua-desync=multidisorder:pos=1,midsld:seqovl=1:strategy=3
--lua-desync=multisplit:pos=1,midsld:seqovl=1:strategy=4
```

**Действие:** добавить как пресет «Универсальная лестница (сообщество)» — заодно проверить на нашем роутере и сравнить нагрузку CPU. Хороший fallback для флапающих провайдеров.

## 4. Форматная совместимость отчётов (БЕСПЛАТНАЯ ИНТЕГРАЦИЯ)

Генератор стратегий tspu-test читает JSON вида {"strategies":[{"working":true,"args":"...","protocol":"..."}]} — это в точности формат нашего /tmp/blockcheckw_scan.json.

Наш circular-builder.lua (строки 57–100) тоже парсит strategies[].args.

Вывод: пользователь zapret2wizard может скопировать наш scan.json в генератор tspu-test и получить 8 вариантов профилей. И наоборот — наш circular-builder может переварить отчёт tspu-test. Взаимная совместимость бесплатна, её можно документировать (кнопка «Экспорт для TSPU test» в UI).

## 5. Анти-адаптивный мониторинг: «Прод-проба» и «Канарейка»

Два лёгких компонента, которых у нас нет в таком виде:

**Прод-проба** (строки 822–867): соединение раз в секунду, 10-секундные окна, первое время отказа фиксируется. Вердикт «ТСПУ адаптивный», если отказы начинаются с N-й секунды (N ≥ 10) — разогрелся реальным трафиком. У нас есть adaptive-фазы скана, но нет этого постоянного лёгкого мониторинга.

**Канарейка** (строки 1061–1099): фоновый curl каждые N секунд через живой Zapret2, история ОК/СБОЙ, ротация лога при 200 КБ (оставляет хвост 30 КБ), пропуск проверок во время теста/валидации. Простая реализация ~40 строк shell.

**Действие (0.37.x):** лёгкая «канарейка» по умолчанию для включённых сервисов (раз в 5 минут, лог в /tmp с ротацией) — деградация видна в истории ДО того, как пропадёт YouTube. Решает Issue #1 (YouTube перестал работать) на уровне детекции.

## 6. Валидатор чужих стратегий (полезно для отладки)

Три приёма, которые стоит перенять:

1. **Детекция «desync function does not exist»** — nfqws2 не знает функцию из чужой стратегии → попытки шли БЕЗ обхода → вердикт «НЕ ПРОВЕРЕНА», а не «не прошла».
2. **Детекция «working without bypass»** — домен открывается без обхода → вердикт о стратегии ничего не доказывает.
3. **Защита от shell-инъекций** в валидаторе: запрет обратной кавычки, $, ;, &, |, <, > — всё остальное легитимно для nfqws2-аргументов.

## 7. Практики тестирования YouTube (связано с нашим Issue #1)

- Видео идёт с ОТДЕЛЬНЫХ узлов *.googlevideo.com, ТСПУ фильтрует их жёстче сайта. Отдельный прогон теста по узлу из DevTools (F12 → Network → videoplayback → скопировать узел до /videoplayback).
- Красные ERR_CONNECTION_ABORTED на videoplayback — прямой признак, что узел нужно тестировать отдельно.
- У нас уже есть yt_video_page-тест, но инструкция для пользователя в UI (куда нажать в DevTools) отсутствует. README tspu-test — готовый текст.

## 8. Пакетирование под OpenWrt 25.x apk (наш больной вопрос)

В workflow build-apk.yml есть готовая схема сборки .apk:

- apk-tools-static 3 из Alpine edge на GitHub Actions → apk.static mkpkg с --info name/version/arch/description/license/depends, --script для pre/post-install/deinstall, --files apk-data.
- Верификация: установка собранного пакета в чистый --root /tmp/troot + grep-проверка маркеров версии в файлах.
- CRLF→LF нормализация, права 755/644, владелец root:root.
- install.sh с авто-детекцией opkg/apk и деавторизацией LuCI через ubus call session destroy после установки.

**Действие:** адаптировать этот workflow для сборки официального .apk luci-app-blockcheckw (мы собирали .zip вручную через PowerShell — это неверный формат). apk-tools-static работает на ubuntu-latest без установки OpenWrt SDK.

## 9. Надёжность процессов (мелкие приёмы)

- **Остановка теста:** TERM → ждать 12 с → kill -9; trap раннера гарантирует запуск Zapret2 обратно. Плюс страховочный флаг /tmp/tspu_test.was.
- **Взаимоисключение** теста и валидатора (оба останавливают Zapret2 — параллельный запуск ломает друг другу nfqueue).
- **DNS-пречек** перед тестом: googlevideo-узлы временные → подсказка закрепить в /etc/hosts; фолбек-проверка через 8.8.8.8. (Связано с нашим MEDIUM-ишью про DNS pin.)
- **FakeIP-стаб детекция** (198.18.x.x при ZeroBlock) → авто-переключение на DoH.

## Что НЕ стоит брать

- **Клиенты для ПК** (Windows/Linux/macOS .bat/.sh) — вне скоупа OpenWrt-службы.
- **Остановку Zapret2 на время теста** — наша служба управляет nfqws2 сама. Наши сканы уже умеют работать поверх работающей службы — это преимущество, не ломать.
- **34-стратегический полный корпус как обязательный** — 5–15 минут на домен слишком долго для автоскана. Классификацию — только как отдельный пользовательский режим.
