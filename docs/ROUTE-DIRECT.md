# Прямой маршрут: домены службы мимо туннеля

Это замена «исключениям туннеля» для роутеров, где маршрутизацией занимается
оркестратор: mihomo, sing-box, v2rayA, своя nft-сборка — служб много, названия
у всех разные. Никаких сторонних API: только локальные списки, локальный
dnsmasq и родные механизмы самого оркестратора.

## Зачем это нужно

`zapret2wizard` обходит DPI только для трафика **без метки туннеля**. Если
оркестратор заворачивает `youtube.com` в туннель, обход простаивает: пакеты
уже помечены и ушли в туннель. Хуже того, часть запросов идёт напрямую, часть
через туннель — YouTube видит разные IP и теряет регион, а Shorts/превью
грузятся рывками.

Правильная схема: **домены, которые обслуживает служба, идут напрямую**, их
режет zapret; остальное (Gemini, банки, геоблок) остаётся в туннеле.

## Два исполнения

### 1. Списковые исключения (основной путь)

У оркестратора почти всегда есть свой список доменов, которые не нужно
заворачивать: он лежит на диске, переживает reload firewall и виден в его
собственном интерфейсе. Служба пишет в этот список управляемый блок:

```
# >>> zapret2wizard direct (managed)
youtube.com
googlevideo.com
youtubei.googleapis.com
...
# <<< zapret2wizard direct (managed)
```

Имя службы и путь к файлу **не зашиты**. Список ищется так:

1. **Автоопределение.** Сканируются `/etc/*/spec.json` — файлы, в которых
   оркестраторы описывают свои списки. Если в спеке есть
   `"domains_file"`/`"prefixes_file"`, путь берётся оттуда, а имя службы —
   из каталога спеки (оно нужно, чтобы перечитать конфигурацию и приостановить
   службу на время подбора).
2. **Явная настройка.** Если у службы нет спеки (или она нестандартная),
   достаточно указать путь и команду перечитывания в UCI — см. ниже.

Почему домены, а не IP:

* работают и IPv4, и IPv6, и QUIC, и клиенты с DoH;
* не нужно угадывать CDN-адреса `googlevideo`;
* перезапуск службы и `reload firewall` ничего не ломают — список лежит в
  пользовательском файле, а не в nft-таблице;
* правки пользователя (банки, госуслуги) сохраняются: блок снимается по
  маркерам, остальные строки не трогаются;
* выключение запоминается: `bypass disable` пишет `route_enabled=0`, и
  `init`/hotplug/cron (они вызывают `bypass_sync sync`) больше не возвращают
  правила — маршрут включается только явной командой или галочкой.
  Исключение одно: при обновлении с версий, где переключателя не было,
  маршрут включается один раз автоматически, если остался хоть один признак
  старого поведения — nft-правила `bcw-bypass`, старая cron-строка
  `bypass_sync enable`, файл `bypass_state.txt` или наш блок в списке;
  иначе исключения пропали бы молча.

После записи служба перечитывает конфигурацию (команда из
`route_list_reload`, иначе `/etc/init.d/<служба> reload`) и проверяет
решение: если задана `route_list_verify` — её кодом возврата, иначе
попаданием домена в список. Результат виден в `bypass status`
(`"verified":true`).

### 2. nft — return до маркировки (запасной путь)

Если списка нет или служба нестандартная, но маршрутизация сделана на nft,
служба ищет таблицы, где есть `mark set`, и в base-цепочке
(`hook prerouting`/`ingress`) ставит правило **перед первой маркировкой**:

```
ip  daddr @bcw_route4 counter return comment "bcw-route"
ip6 daddr @bcw_route6 counter return comment "bcw-route"
```

Не в начало цепочки, а именно перед `mark set` — поэтому фильтры
интерфейсов и адресов, которые оркестратор ставит раньше, продолжают
работать. Наборы заполняются адресами из локального dnsmasq (A + AAAA) и
статическими IP/CIDR из `user.lst`.

Сторож проверяет только свои цепочки (не весь ruleset), пересматривает
цели раз в 10 минут и пересобирает правила, если оркестратор пересоздал
таблицу.

## Команды

```sh
blockcheckw-helper bypass enable      # применить (исполнение определится сам)
blockcheckw-helper bypass status      # исполнение, домены, правила, проверка
blockcheckw-helper bypass domains     # что именно идёт напрямую
blockcheckw-helper bypass verify      # проверка решения/покрытия
blockcheckw-helper bypass rebuild     # пересобрать IP-кэш и правила
blockcheckw-helper bypass disable     # вернуть домены в туннель
blockcheckw-helper bypass backend auto|list|nft   # выбрать исполнение

blockcheckw-helper youtube_audit      # веб + превью + API + CDN + маршрут
blockcheckw-helper bypass explain www.youtube.com  # куда пойдёт домен
```

То же из LuCI: карточка **«Обход туннелей»** на главной. Для спискового
исполнения она показывает «доменов напрямую» и результат проверки, для nft —
правила/IP. Кнопка **«Проверить YouTube»** на карточке запускает
`youtube_audit`.

## Настройки (UCI)

```sh
uci set zapret2wizard.main.route_enabled=1      # включает маршрут (по умолчанию 0)
uci set zapret2wizard.main.route_backend=auto   # auto | list | nft
uci set zapret2wizard.main.route_services='youtube discord'
uci set zapret2wizard.main.route_extra='example.com 1.2.3.0/24'
uci commit zapret2wizard
```

* `route_enabled=0` по умолчанию: маршрут правит чужие списки и nft-таблицы,
  поэтому сам не включается ни при старте, ни по cron. Галочка в карточке
  LuCI делает то же, что `bypass enable`.
* `route_backend=auto` — списковое исполнение, если нашёлся список, иначе nft.
* `route_services` — какие сервисы выводить. По умолчанию определяется по
  включённым стратегиям (`BlockcheckW_YouTube`, YTApi, Discord и т.д.).
  `none` — только `user.lst`.
* `route_extra` — добавить домены/IP без редактирования файлов.

### Своя служба маршрутизации

Если автоопределение не сработало, укажите всё явно — код не нужно менять:

```sh
uci set zapret2wizard.main.route_list_file='/etc/моя-служба/direct.lst'
uci set zapret2wizard.main.route_list_pfx='/etc/моя-служба/direct.pfx'   # необязательно
uci set zapret2wizard.main.route_list_reload='моя-служба reload'
uci set zapret2wizard.main.route_list_verify='моя-служба explain {}'     # 0 = напрямую
uci set zapret2wizard.main.route_list_ips=0    # 1 — закрепить ещё и IP
uci commit zapret2wizard
blockcheckw-helper bypass enable
```

`route_list_spec` позволяет указать конкретную спеку, если в системе их
несколько.

## Что где лежит

| Путь | Назначение |
|---|---|
| `/etc/zapret2wizard/route/*.lst` | встроенные списки сервисов (перезаписываются при обновлении) |
| `/etc/zapret2wizard/route/user.lst` | ваши домены/IP (не перезаписывается) |
| `/etc/zapret2wizard/route_domains.txt` | итоговый список после фильтра исключений |
| `/etc/zapret2wizard/route_state.txt` | цепочки, куда поставлены nft-правила |
| `/etc/zapret2wizard/route_backend` | `list`, `nft` или `none` |
| список оркестратора | наш блок по маркерам внутри файла, который нашла служба |
| `/tmp/bcw_route.log` | журнал применения |
| `/tmp/bcw_route_verify.json` | последний результат проверки |

Рядом с найденным списком создаётся резервная копия `*.bcw.bak` (один раз).

## Откат

```sh
blockcheckw-helper bypass disable
```

Снимает управляемый блок из списка и префиксов, удаляет nft-правила и наборы,
возвращает домены в туннель.

## Ограничения

* Служба может перегенерировать свою спеку из панели. Список при этом
  сохраняется, а сторож переприменяет блок, если файл изменили. Если панель
  убрала сам список из спеки — служба переключится на nft-исполнение.
* Домены в `srs`-списках не разворачиваются; для YouTube это не нужно, там
  обычные домены.
* `route_list_ips=1` может вывести из туннеля соседний сервис на общем
  адресе. Включайте осознанно.
* Возврат в туннель уже открытых вкладок — перезагрузка страницы или
  `bypass disable/enable`; conntrack служба не чистит намеренно, чтобы не
  рвать просмотр.
