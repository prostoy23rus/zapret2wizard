# Прямой маршрут для сервисов, которые держит zapret

По умолчанию `steer` уводит почти весь заблокированный трафик в туннели
(`zm_vpn` / `zm_vpn2`). Из-за этого DPI-обход `zapret2wizard` простаивает:
его правила применяются только к пакетам без метки `0x40000000`, а метку
ставит steer для туннельного трафика.

Чтобы обход работал по назначению, часть сервисов переведена на **прямой
маршрут**: они идут через провайдера, а режет их zapret.

## Что изменено на роутере

1. Список доменов:

```
/etc/zm-steer/user/direct-zapret.lst
```

Текущее содержимое: `bbc.com`, `www.bbc.com`, `facebook.com`,
`www.facebook.com`, `linkedin.com`, `www.linkedin.com`, `x.com`,
`twitter.com`, `rutracker.org`.

2. В `/etc/steer/spec.json` добавлены:

```json
"lists": {
  "bcw_direct": { "domains_file": ["/etc/zm-steer/user/direct-zapret.lst"] }
},
"rules": [
  { "name": "Исключения", ... },
  { "name": "Zapret2Wizard direct", "to": "bcw_direct", "out": "zm_direct", "resolve": "realip" }
]
```

Правило стоит **сразу после «Исключений»**, чтобы перебивать «Геоблок»,
«Новости», «block» и не уводить трафик в туннель.

3. Применение: `steer reload`.

Бэкап исходного файла: `/etc/steer/spec.json.bcw-backup`.

## Проверка пользы

С ПК при включённом zapret:

| Сайт | zapret включён | zapret остановлен |
|---|---|---|
| bbc.com | 200, 663 КБ, 0.8 с | таймаут |
| facebook.com | 200, 378 КБ, 0.6 с | таймаут |
| linkedin.com | 200, 140 КБ, 0.7 с | таймаут |

То есть трафик действительно идёт через DPI-обход, а не через туннель.

## Важно

`/etc/steer/spec.json` управляется панелью RouteRich: при изменении
настроек steer правило может быть перегенерировано. Тогда список и правило
нужно добавить заново (файл списка при этом сохраняется).

`meduza.io` в список не входит: провайдер подменяет DNS (`8.6.112.0`,
`8.47.69.0`), поэтому её нужно держать в туннеле, где DNS идёт через DoH.

## Откат

```sh
cp /etc/steer/spec.json.bcw-backup /etc/steer/spec.json
steer reload
```
